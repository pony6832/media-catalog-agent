# Media Catalog A+ Stable v1.2 設計規格

## 1. 目的

在既有 Media Catalog Agent 原始版本上進行穩定擴充，優先解決長影片分析不完整、Excel 路徑無法直接開啟媒體、批次偶發停止，以及缺少可見執行狀態四個問題。

本版正式名稱為 **Media Catalog A+ Stable v1.2**，開發分支為 `codex/legacy-a-plus-v1.2`。它沿用原始版命令、SQLite、Excel 與 `媒體整理成果`，不加入 Hybrid Lite 的獨立成果目錄、4B／8B 路由、搜尋或向量功能。

原始版基準為 Git commit `bfa92f7`。隔離工作區完成依賴安裝後，基線測試為 `72 passed, 1 skipped`。

## 2. 保留的原始版契約

自然語言入口保持不變：

```text
整理並分析這個資料夾：D:\素材
```

成果位置保持不變：

```text
D:\素材\媒體整理成果\
├─ catalog.sqlite
├─ 媒體清冊.xlsx
└─ 工作暫存\
```

來源媒體保持原位，不移動、不改名、不修改 metadata。掃描、分析及恢復流程均繼續使用來源完整性快照與 SHA-256 驗證。

既有 `media-catalog` CLI 必須保持可供自動化與測試使用的無 UI 模式；由 Codex Skill 啟動的分析 launcher 則預設開啟 A+ 狀態 UI。

## 3. 整體架構

```text
對話指令
  -> Skill launcher
  -> Tkinter 狀態 UI
  -> Supervisor 監督器
  -> 獨立分析 worker
       -> 掃描照片與影片
       -> 照片：沿用本機 Qwen3-VL 8B 分析
       -> 影片：場景分段與關鍵影格選擇
            -> 本機 Qwen3-VL 8B 片段分析
            -> 品質不足時 Gemini 3.7 Flash 強化
            -> 本機彙整整支影片結果
       -> 逐片段 SQLite checkpoint
       -> 原子重建 Excel
  -> UI 每秒讀取 SQLite 狀態
```

UI 與 worker 必須是不同程序。UI 不直接執行 FFmpeg、Ollama 或 Gemini，也不得因主執行緒等待分析而失去回應。

## 4. 長影片場景分段

### 4.1 分段規則

影片使用 FFmpeg 場景變化偵測，預設 scene threshold 為 `0.35`。偵測到明顯畫面轉場時建立片段邊界。

為避免訪談、會議或固定鏡頭影片長時間沒有轉場，任何單一片段不得超過 300 秒；超過時以 300 秒為上限建立保護切點。最後不足 2 秒的尾段併入前一片段，避免產生無分析價值的極短片段。

分段只建立時間範圍與暫存預覽，不剪輯或重封裝原始影片。

### 4.2 候選與代表影格

每個片段先在相對時間 20%、50%、80% 位置建立候選影格；若片段包含場景轉場邊界，另加入邊界後第一張穩定影格。候選影格一律縮放至最長邊不超過 1280 像素並保存於 `工作暫存`。

`FrameSelector` 使用下列固定訊號排序：

- 影像清晰度，排除嚴重模糊影格。
- 影格間視覺差異，避免選到近乎相同的畫面。
- OCR 文字密度，保留具有標題、字幕、簡報或告示的畫面。
- 場景邊界與動作變化，優先保留能代表事件變化的畫面。

選取數量：

- 靜態且候選高度相似：1 張。
- 有明顯內容差異或文字資訊：2 張。
- 多場景、動作變化大或文字密集：3 張。

每個片段不得少於 1 張或多於 3 張。無法產生有效影格時，該片段標記失敗並保留可行動錯誤，不得猜測內容。

## 5. 本機分析與 Gemini 強化

### 5.1 本機優先

每個影片片段先以既有本機 `Qwen3-vl:8b-instruct` 分析，輸出繁體中文的：

- 內容描述。
- 重點。
- 關鍵字。
- 可觀察人物、動作、場景與畫面文字。

照片維持原始版本機分析，不在 A+ 第一階段自動呼叫 Gemini。

### 5.2 Gemini 升級條件

只有本機片段結果符合下列任一條件時，才可使用 Gemini：

- JSON 無效或必要欄位空白。
- 描述過於空泛，無法指出人物、場景或主要事件。
- OCR 文字密集，但本機結果沒有反映主要文字資訊。
- 多人物、多場景或動作變化造成內容不一致。
- 不同代表影格的本機判斷互相衝突。

Gemini 預設模型使用已實際測試成功的 `gemini-3.7-flash`。只有使用者日後明確設定 `GEMINI_MODEL` 環境變數時才可覆寫；未設定時不得自動改用其他模型。API Key 只從 Windows 環境變數 `GEMINI_API_KEY` 讀取。

### 5.3 傳送限制與額度

Gemini 只接收：

- 該片段選出的 1～3 張縮放代表影格。
- 該片段 OCR 文字。
- 本機初步摘要。

不得傳送完整影片、音訊、未縮放原始照片、完整本機路徑或不必要的 metadata。

每支影片最多強化 12 個片段，每支影片最多傳送 36 張縮放影格。額度計數保存在 SQLite；中斷續跑不得重新取得 12 次額度。達到上限後，其他不足片段保留最佳本機結果並標記 `待人工確認`。

Gemini 逾時、配額不足、拒絕或網路失敗時，保留最佳本機結果、記錄經清理的錯誤類型並繼續。不得因 Gemini 失敗中止影片或整批工作。

### 5.4 整支影片彙整

所有片段完成後，由本機 Qwen3-VL 8B 根據片段文字結果彙整整支影片的描述、重點與關鍵字。此彙整不額外呼叫 Gemini，且不得把片段暫存路徑寫入最終內容。

## 6. SQLite 資料與升級安全

### 6.1 升級前備份

需要修改資料結構時，先建立：

```text
媒體整理成果\APlus備份\YYYYMMDD-HHMMSS\
├─ catalog.sqlite
└─ 媒體清冊.xlsx
```

備份檔必須存在、大小非零，SQLite 備份必須通過完整性檢查。只有驗證成功後才可開始 schema migration。升級失敗時停止並保留既有資料，不得繼續分析。

### 6.2 `video_segments`

每個片段保存：

- `segment_id`、`media_record_id`。
- `start_seconds`、`end_seconds`。
- `status`：`pending`、`processing`、`completed`、`failed`。
- 代表影格暫存路徑 JSON。
- 本機描述、重點及關鍵字。
- Gemini 是否呼叫、模型與強化結果。
- `needs_review`。
- `retry_count`、`crash_count`、錯誤類型。
- 建立時間、更新時間及最後心跳。

`media_record_id + start_seconds + end_seconds` 必須唯一，使重新分段與續跑不會重複建立同一片段。

### 6.3 `analysis_runs`

每次工作保存：

- 根目錄與 run ID。
- 影片數、照片數、媒體總數及總位元組數。
- 已完成、未完成及失敗數。
- 目前媒體與片段。
- worker PID、工作狀態與最後心跳。
- 是否要求安全停止。
- worker 自動恢復次數。

每完成一個片段就提交 SQLite checkpoint。整支影片完成後才更新既有 `media_records` 的最終分析欄位。

## 7. Excel 超連結與人工審核

`媒體清冊.xlsx` 的「完整路徑」儲存格顯示原始完整 Windows 路徑，並使用該路徑轉換出的本機 file URI 作為 hyperlink。點擊影片時由 Windows 預設播放器開啟；照片由預設照片程式開啟。

規則：

- 只連結原始媒體，不連結代表影格或其他暫存檔。
- 原始檔不存在時只顯示路徑文字，不建立失效連結。
- 儲存格套用 Excel Hyperlink 樣式，但顯示文字仍是完整路徑。
- 原子重建 Excel 前，先以完整路徑讀回既有工作簿的 `已審核` 狀態。
- 自動分析不得覆蓋 `已審核` 狀態；明確重新分析仍需由後續獨立規格授權。

API Key、Gemini request body、完整 response payload 與可能含密鑰的錯誤內容不得寫入 SQLite 或 Excel。

## 8. Supervisor、心跳與恢復

### 8.1 心跳

worker 由獨立心跳執行緒每 5 秒更新 SQLite。UI 每秒讀取一次狀態：

- 15 秒內有心跳：綠燈、`執行中`。
- 尚未開始、已安全停止、worker 不存在或心跳超過 15 秒：紅燈。
- 自動恢復期間：紅燈並顯示 `正在重新啟動`。

### 8.2 階段逾時

預設逾時：

- 單支影片分段與影格擷取：20 分鐘。
- 單片段本機模型分析：10 分鐘。
- 單次 Gemini：90 秒。

每個階段失敗或逾時時自動重試一次。第二次仍失敗則記錄原因並繼續下一片段。

### 8.3 worker 意外結束

UI／Supervisor 偵測到 worker 消失或心跳超時時，自動重新啟動一次。新 worker 取得既有分析鎖後，將 stale `processing` 片段重新排入，從最近 checkpoint 接續。

同一片段若連續兩次造成 worker 異常結束，標記該片段失敗並跳過，防止無限重啟。整批結束時只要仍有失敗或未完成資料，就輸出 `MEDIA_ANALYSIS_INCOMPLETE`，不得宣稱完成。

電腦重新開機或 UI 已完全關閉後不自動常駐啟動；使用者再次輸入相同指令，即可由 SQLite 接續。

### 8.4 安全停止

按下 `安全停止` 時，只設定 SQLite 的 stop request。worker 完成目前片段、寫入 checkpoint、釋放分析鎖後退出。不得直接終止正在寫入 SQLite 或 Excel 的程序。

關閉 UI 時提供 `安全停止後關閉` 與 `取消關閉`；A+ 不留下隱藏背景 worker。

### 8.5 Excel 鎖定

片段與媒體分析先保存至 SQLite。Excel 被開啟鎖定時，分析可繼續，UI 顯示 `等待 Excel 關閉`。批次結束或 Excel 可寫時，再由 SQLite 原子重建工作簿。Excel 尚未同步成功時不得輸出 `MEDIA_ANALYSIS_READY`。

## 9. 精簡狀態 UI

使用 Python 內建 Tkinter 製作單視窗面板，不新增 Electron、瀏覽器框架或常駐背景服務。

UI 顯示：

```text
● 執行中
指定路徑：D:\素材
影片：72　影像：28　總容量：18.6 GB
進度：55 / 100　未完成：45
目前：訪談片段_027.mp4｜第 6 / 14 段
Gemini 強化：7 / 12
[███████████░░░░░░░░] 55%
```

媒體數量與容量只統計指定根目錄中的支援來源媒體，永久排除 `媒體整理成果`、符號連結與 reparse point。`完成／總數` 以媒體項目計算，不以片段數計算；目前影片另顯示片段進度。

按鈕：

- `開始／繼續`。
- `安全停止`。
- `開啟 Excel`。
- `開啟成果資料夾`。

由對話指令啟動時，launcher 將使用者根目錄傳入 UI；UI 驗證路徑、顯示掃描統計並自動開始，不需要使用者再次選擇資料夾或按開始。

## 10. 開發階段

### 階段 1：原始版穩定化

- 建立可重現測試環境。
- 完成 CP950 安全輸出修復。
- 加入心跳、逾時、有限重試、片段 checkpoint 與 worker 恢復基礎。

### 階段 2：Excel 與長影片基礎

- 加入完整路徑 hyperlink。
- 加入場景分段、300 秒保護切分及每段 1～3 張代表影格。
- 加入安全 schema migration 與 APlus 備份。

### 階段 3：Gemini 精準強化

- 加入本機品質判定。
- 加入 `gemini-3.7-flash` 安全客戶端。
- 加入每支影片 12 片段／36 影格限制與失敗降級。

### 階段 4：精簡 UI

- 加入 Tkinter 面板與 Supervisor。
- 加入紅／綠燈、統計、進度、目前項目、Gemini 次數與安全停止。
- 修改 Skill launcher，使對話指令自動開啟 UI 並開始分析。

每個階段完成後必須能單獨測試與提交；不得等全部功能完成才第一次整合驗證。

## 11. 不屬於 A+ v1.2 的範圍

- Hybrid Lite 獨立 CLI 與成果目錄。
- Qwen3-VL 4B／8B 自動路由。
- 自然語言搜尋與搜尋結果排名。
- embeddings、向量資料庫或網頁 UI。
- Whisper、音訊逐字稿與完整影片雲端上傳。
- 開機自動執行或隱藏常駐服務。
- 修改原始媒體 metadata。

## 12. 驗收標準

1. 原始版完整 pytest 套件通過，既有 72 個通過測試不退步。
2. 中文與 CP950 不支援字元的檔名不會讓批次中止。
3. 多場景測試影片依轉場分段；長時間單一場景每段不超過 300 秒。
4. 每個有效片段只選取 1～3 張縮放代表影格。
5. Gemini 只在本機結果不足時呼叫，模型為 `gemini-3.7-flash`。
6. 每支影片 Gemini 強化不超過 12 個片段、傳送不超過 36 張影格；續跑不重置額度。
7. API Key 不出現在 Git、程式、SQLite、Excel、日誌、錯誤訊息或測試快照。
8. 點擊 Excel `完整路徑` 可由 Windows 預設程式開啟存在的原始媒體。
9. Excel 原子重建後保留使用者的 `已審核` 狀態。
10. 模擬本機模型逾時、Gemini 失敗、worker 消失、心跳超時及 Excel 鎖定時，批次能恢復、降級或提供可行動錯誤。
11. UI 綠燈只在 15 秒內有心跳時顯示；其他狀態顯示紅燈及原因。
12. UI 的影片數、影像數、總容量、完成／未完成數與 SQLite 一致。
13. 中途停止後重新執行，不重跑已完成片段。
14. 只有最終 `failed=0`、`remaining=0` 且 Excel 同步成功時輸出 `MEDIA_ANALYSIS_READY`。
15. 分析前後所有來源照片與影片的 SHA-256 完全一致。
16. 一般測試完全 mock Gemini；即時 API 測試只能在明確設定 opt-in 環境變數時執行。
17. 新電腦依安裝文件可重新建立 Python runtime、安裝依賴並啟動 A+ UI，不複製其他電腦的 `.runtime` 或 `.tools`。
