# 媒體清冊第二版：安全預覽分析設計

## 目標

在第一版已建立的待處理清冊上，離線分析全部待處理照片與影片，產生內容描述、重點與關鍵字，並逐項同步到 SQLite 與 Excel。第二版是「預覽分析」階段：完成結果必須標示為「待確認」，不得寫入媒體 metadata、建立 Markdown sidecar、移動、重新命名或刪除原始媒體。

本次實際目標資料夾為 `D:\【AIGC-ALL】\2026馬年賀卡AI`，目前有 17 張圖片與 3 部影片，共 20 個待處理項目。使用者已明確批准處理全部待處理項目。

## 隱私與安全邊界

- 所有視覺理解使用本機 Ollama 模型 `Qwen3-vl:8b-instruct`。
- Watch 必須使用 `--no-whisper`，不得將音訊送到 Groq、OpenAI 或其他外部 API。
- 呼叫子程序時移除常見雲端 API 金鑰，並設定 Hugging Face、Transformers 與 npm 的離線環境旗標。
- MCP Video Analyzer 僅處理本機檔案，使用固定版本 `0.8.0`，不得以 `latest` 安裝或執行。
- 第二版只讀取原始媒體。允許寫入的範圍限於根目錄下的 `媒體整理成果`。
- 實際全量執行前後，比對每個來源檔的完整路徑、大小、修改時間與既有 SHA-256 指紋；任何來源變動都視為驗證失敗。

## 使用者入口

Skill 接受：

```text
分析全部待處理：D:\【AIGC-ALL】\2026馬年賀卡AI
```

入口只處理該根目錄既有 `catalog.sqlite` 中狀態為 `pending` 的紀錄。已分析完成的項目必須略過；失敗項目只在使用者明確要求重試時重新排入。

成功完成整批工作時輸出一行機器可讀摘要：

```text
MEDIA_ANALYSIS_READY analyzed=<n> failed=<n> skipped=<n> remaining=<n> catalog=<absolute-xlsx-path>
```

若根目錄、清冊、Ollama 或指定模型在開始前不可用，輸出 `MEDIA_ANALYSIS_ERROR <原因>` 並停止，不得猜測替代工具或路徑。Watch 與 MCP 是逐項影片依賴：其中一套可用時使用主流程或備援；兩套都不可用時只讓影片項目失敗，圖片仍繼續。個別素材失敗不使整批程序提前結束；摘要必須包含失敗數，Excel 必須保留各項精確錯誤。

## 分析架構

### 圖片

圖片直接送入 `Qwen3-vl:8b-instruct`。模型只能根據本機圖片輸出符合下列結構的 JSON：

- `description`: 非空字串。
- `highlights`: 字串陣列。
- `keywords`: 字串陣列。

不符合結構、無法解析、逾時或模型程序非零結束，都視為該項失敗。

### 影片

影片採用單次主流程與條件式備援：

1. 先以 Watch Skill 呼叫 claude-video 的本機擷取腳本，使用 `efficient`、最多 12 張代表畫面與 `--no-whisper`。
2. 只有 Watch 執行失敗或沒有產生代表畫面時，才改用 MCP Video Analyzer `0.8.0` 擷取最多 12 張畫面及本機 OCR。
3. 任一擷取器成功後，只呼叫一次 Qwen3-VL 產生描述、重點與關鍵字。
4. Qwen3-VL 本身失敗時不再重跑另一個擷取器，避免重複分析與掩蓋模型錯誤。

Watch 是 claude-video 的操作介面，兩個名稱代表同一條主流程，不得重複呼叫。MCP 只作失敗備援，不對每部影片雙跑。

## 批次處理與狀態

新增 `analyzed` 狀態，Excel 顯示為「待確認」。單項狀態流轉為：

```text
待處理 -> 處理中 -> 待確認
                  -> 失敗
```

批次處理依 SQLite 的穩定順序逐項執行：

1. 將目前項目標為 `processing` 並更新 Excel。
2. 執行圖片或影片分析。
3. 成功時保存三項分析結果、清除舊錯誤並標為 `analyzed`。
4. 失敗時保存精確錯誤並標為 `failed`。
5. 每一項完成後重新輸出 Excel，確保中途中止時已完成結果仍可見。

重新執行一般批次只選取 `pending`，因此不重複分析 `analyzed`。若程序在單項分析期間意外中斷，該項會停在 `processing`；恢復命令必須由使用者明確使用，將殘留的 `processing` 項目重新排入，不得在可能有另一個程序執行時自動重跑。

## 元件邊界

- `FallbackVideoExtractor`：封裝 Watch 主流程與 MCP 備援規則，對外只回傳一致的 `VideoEvidence`。
- `LocalAnalyzer`：圖片直接分析；影片只消費 `VideoEvidence`，不決定備援策略。
- 批次服務：選出待處理紀錄、逐項更新狀態、捕捉個別錯誤並刷新 Excel。
- CLI：解析根目錄、執行依賴預檢、呼叫批次服務並輸出固定摘要。
- `media-inventory` Skill：從對話取出唯一根目錄並呼叫私有 runtime，不自行解析資料庫或模型輸出。

每個元件只透過既有 `Analysis`、`VideoEvidence`、`CatalogDatabase` 與 `MediaWorkspace` 介面交換資料，避免 CLI、Skill 或安裝器直接操作分析內部狀態。

## 工具安裝與生命週期

- Watch 使用已安裝於 Codex Skills 目錄的 `scripts/watch.py`，啟動前驗證檔案存在並執行靜默預檢。
- MCP Video Analyzer 安裝在正式 `media-inventory` Skill 的私有工具目錄，不依賴 Git worktree 中被忽略的 `.tools`。
- 安裝器必須鎖定並驗證 MCP 套件名稱與版本 `0.8.0`，然後執行一個本機測試素材的結構化輸出檢查。
- Skill 更新沿用第一版的可逆流程：先把現有正式 Skill 移到時間戳備份，再安裝新版；失敗時保留備份與失敗副本，不自動覆寫或刪除。

## 錯誤處理

- 根目錄、SQLite 或 Excel 不存在：整批開始前失敗，不建立替代位置。
- Ollama 不存在或指定模型未安裝：整批開始前失敗。
- Watch 不可用但 MCP 可用：影片可直接進入既定備援；圖片不受影響。
- Watch 與 MCP 都不可用：圖片仍可處理；每部影片各自標示失敗，整批繼續。
- 媒體在掃描後消失或指紋不符：該項失敗，不分析替代檔案。
- 無效模型 JSON、逾時或程序錯誤：該項失敗並保存精確、去除敏感資訊的錯誤摘要。
- Excel 暫時無法寫入：停止批次，保留已提交的 SQLite 狀態並回報 Excel 路徑與錯誤，避免宣稱清冊同步完成。

## 測試與驗證

實作採測試先行，至少涵蓋：

- 圖片不呼叫影片擷取器。
- Watch 成功時 MCP 完全不執行。
- Watch 失敗時 MCP 只執行一次。
- Watch 與 MCP 都失敗時，該影片失敗但下一項繼續。
- 成功分析轉為 `analyzed`／「待確認」，不是 `completed`／「完成」。
- 每項結束後 SQLite 與 Excel 同步更新。
- 重跑時略過已分析項目，不自動重試失敗項目。
- CLI 依賴預檢與固定摘要格式。
- Skill 私有 Watch、MCP、Ollama 路徑解析與固定版本驗證。
- 測試來源檔的 bytes、大小與修改時間在處理前後完全一致。

完成單元與整合測試後，先以一張測試圖片及一部測試影片執行本機冒煙測試。只有冒煙測試產生合法 JSON、Excel 顯示「待確認」、來源檔不變後，才執行已批准的 20 項全量分析。全量執行後再次核對來源快照，並回報成功、失敗、略過與剩餘數量。

## 本版不做

- 寫入 EXIF、XMP 或影片 metadata。
- 建立 Markdown sidecar。
- 備份、移動、重新命名或刪除來源媒體。
- 模糊搜尋、語意搜尋或嵌入索引。
- Google Drive 或其他雲端同步。
- 排程、自動監看新檔或背景常駐分析。

上述能力必須等使用者檢查「待確認」結果並明確批准後，才能進入下一個設計與實作週期。

## 驗收條件

1. 使用者能以單一路徑對話命令處理全部待處理項目。
2. 17 張圖片使用本機 Qwen3-VL；3 部影片使用 Watch／claude-video 主流程並僅在必要時使用 MCP 備援。
3. 每項結果含描述、重點、關鍵字，並同步存在 SQLite 與 Excel。
4. 成功項目顯示「待確認」，失敗項目有可理解原因，單項失敗不阻止後續項目。
5. 執行過程不呼叫雲端分析服務，且全部 20 個來源檔在前後快照中完全不變。
