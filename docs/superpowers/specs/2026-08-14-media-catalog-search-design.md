# 影片照片資料庫整理 Agent：第一版設計規格

## 目的

建立一個可重複使用的本機 Codex Skill（暫稱「媒體整理與搜尋」），集中整理影片與照片。它會遞迴掃描指定資料夾，讓使用者在待處理清單中選取素材，再以本機模型產生易讀描述、重點與關鍵字，並把結果同步寫入媒體 metadata、同名 Markdown 與 Excel 清冊。

第一版的核心原則是：離線、可還原、先人工選取再處理、結果好閱讀。

## 已確認的限制與決策

- 不呼叫外部 API，也不將媒體、畫面、音訊、描述或索引送到雲端做分析。
- 使用者已有本機 Ollama 的 Qwen3-VL 8-bit 模型，作為照片與影片畫面的理解引擎。
- Google Drive 只用來同步使用者指定的 Excel 清冊與備份成果；它不是分析服務。
- 使用者要的是一個新的整合 Skill，不是常駐 Agent。未來可在流程穩定後加上自動化 Agent。
- 現有能力以 `watch`、`extracting-structure`、`asking-with-evidence` 為基礎；新 Skill 負責整合流程與資料產物，不複製其內部實作。
- 第一版不保存完整逐字稿、不產生章節、不做複雜分類。

## 影片工具整合

第一版以輕量、可替換的本機影片擷取介面整合三個名稱，但不把它們誤當成三套獨立推論引擎：

- `watch-skill` 是 Codex 的主要影片工作流程入口。
- `claude-video` 是目前 `watch-skill` 所使用的底層專案與擷取實作；同一項影片分析不得因兩個名稱而重複執行。
- `guimatheus92/mcp-video-analyzer` 提供另一個本機擷取後端，第一版只使用本機檔案的 metadata、代表影格與 OCR 結果。

兩個後端都必須透過參數陣列啟動本機子程序，輸出正規化為同一份代表影格與警告資料。`mcp-video-analyzer` 必須使用預先安裝、固定版本的本機命令；不得在處理期間使用 `npx -y ...@latest`、遠端影片 URL、雲端摘要或外部轉錄服務。Qwen3-VL 仍是唯一的內容描述、重點與關鍵字生成引擎。

預設先使用 `watch-skill`／`claude-video`；若設定選用 `mcp-video-analyzer`，則使用其本機 CLI。後端不可用或回傳不完整資料時，記錄精確錯誤並停止該項目，不在同一次處理中自動改用可能呼叫網路的路徑。

## 第一版範圍

### 輸入與掃描

使用者手動指定一個本機根資料夾。掃描必須包含所有子資料夾，找出支援的影片與照片；每個項目以完整路徑與檔案指紋去重。掃描只建立或更新「待處理」清冊，絕不改動媒體檔案。

### 使用者選取與本機分析

使用者從待處理清單選擇一個或多個項目才開始處理。照片直接交由本機 Qwen3-VL 分析；影片先由既有 `watch` 能力擷取具代表性的畫面並建立本機索引，再由 Qwen3-VL 根據畫面產出下列三項：

1. 內容描述：一句到一段的清楚自然語言描述。
2. 重點：少量可快速瀏覽的視覺事件、人物、場景或主題重點。
3. 關鍵字：可搜尋的標籤集合。

不得把未驗證的模型輸出寫成事實；若分析不足、媒體損壞或模型失敗，項目必須保留原狀並標示失敗原因。

### 寫入與可還原性

對每個成功分析的項目，依序執行：

1. 建立可還原備份，不覆蓋既有備份。
2. 僅在格式支援且寫入驗證通過時，將 `Title`、`Description`、`Keywords`、`DateCreated`、`CreatorTool` 寫入原始媒體 metadata。
3. 建立與原檔同名的 Markdown sidecar。
4. 更新 Excel 清冊。
5. 更新本機搜尋索引。

若 metadata 格式不支援、原檔正被使用、備份失敗或寫入驗證失敗，停止該項目的後續寫入，保留原檔並在 Excel 記錄精確原因。Markdown 與清冊不得把此類項目標成完成。

## 資料產物

### 原始媒體 metadata

採用各格式可支援的標準欄位：標題、描述、關鍵字、建立／拍攝時間與處理工具資訊。不同格式可寫欄位不同時，記錄實際寫入欄位與限制。

### 同名 Markdown

Markdown 是一般使用者優先閱讀與手動補充的資料，不以 JSON 作為主要介面。每份檔案包含：

- 檔案名稱、完整路徑、類型、大小與可取得的拍攝／建立時間
- 處理狀態與處理時間
- 內容描述
- 重點
- 關鍵字
- 寫入的 metadata 欄位、備份位置及錯誤（若有）

### Excel 清冊

Excel 是單一清冊來源，放在使用者指定、已由 Google Drive 同步的資料夾。欄位如下：

| 欄位 | 用途 |
| --- | --- |
| 狀態 | 待處理、處理中、完成、略過、失敗 |
| 檔名 | 原始檔案名稱 |
| 完整路徑 | 可直接開啟的本機路徑 |
| 媒體類型 | 照片或影片及格式 |
| 內容描述 | 本機模型產生的摘要 |
| 重點 | 簡短重點集合 |
| 關鍵字 | 可篩選、可搜尋的關鍵字 |
| 拍攝時間 | 原檔可取得時填入 |
| 處理時間 | 最後成功處理時間 |
| Markdown 路徑 | 同名 sidecar 位置 |
| 備份路徑 | 寫入前建立的備份位置 |
| 錯誤原因 | 失敗或略過時的可行動說明 |

## 本機搜尋

搜尋讀取 Excel、Markdown 及本機索引；結果必須提供匹配原因、摘要、原檔完整路徑與 Markdown 路徑。

- 模糊搜尋處理部分字詞、常見錯字與近似拼寫。
- 語意搜尋以獨立的本機文字嵌入模型建立索引，理解相近意思。
- Qwen3-VL 專責媒體理解；文字嵌入模型專責搜尋，不呼叫外部 API。

## 使用流程

1. 執行「掃描資料夾」：遞迴加入新素材到 Excel 待處理清單。
2. 使用者在清冊或 Skill 指令中選擇待處理素材。
3. 執行「處理待處理項目」：本機分析、備份、metadata 寫入、Markdown、Excel 與索引更新。
4. 執行「搜尋素材」：以關鍵字、片段、錯字或自然語句取得相近結果。

## 對話式單一路徑入口

使用者可在 Codex 對話中貼上一個 Windows 本機資料夾路徑，例如：

```text
D:\家庭照片影片
```

新 Skill 將這個路徑視為要掃描的媒體根目錄，不另外建立「你要整理的照片影片資料夾」。它先驗證路徑存在、確實是資料夾、不是磁碟根目錄，也不是既有的成果子目錄；驗證通過後，自動解析並建立下列固定結構：

```text
D:\家庭照片影片\
├─ 原本的照片與影片
└─ 媒體整理成果\
   ├─ 媒體清冊.xlsx
   ├─ catalog.sqlite
   ├─ Markdown\
   ├─ 備份\
   ├─ 索引\
   └─ 工作暫存\
```

這個入口取代原本需要分別提供媒體根目錄、資料庫路徑與 Excel 路徑的操作方式。所有衍生路徑都由同一個路徑配置物件產生，避免對話中重複貼路徑或手動組合路徑。

### 首次貼上路徑時的動作

1. 以唯讀方式驗證根目錄與檢查寫入成果目錄的權限。
2. 建立缺少的成果子目錄；既有成果不得覆蓋或清空。
3. 遞迴掃描根目錄中的支援媒體，但永久排除完整的 `媒體整理成果` 子樹、符號連結與 Windows reparse point。
4. 建立或更新 `catalog.sqlite` 與 `媒體清冊.xlsx`。
5. 在對話中回報新增、既有、略過與錯誤數量，並提供清冊完整路徑。

首次動作只建立待處理清單，不自動分析所有素材，也不修改原始媒體。使用者仍須在下一步明確選取項目或下達「處理全部待處理項目」指令，才開始本機模型分析與後續安全寫入流程。

### 重複使用與失敗處理

- 再次貼上同一根目錄時，重用既有資料庫與清冊，只加入新檔案或更新偵測到的內容變更。
- 若貼上的是檔案、磁碟根目錄、成果目錄、找不到的路徑或無法建立成果目錄，停止並在對話回報可行動錯誤；不得退回其他目錄猜測執行。
- 若掃描或 Excel 更新失敗，保留既有成果與原始媒體，不把項目標記為完成。
- 對話入口與未來 CLI 必須呼叫同一個 bootstrap/scan 服務，避免兩套不同的路徑與安全規則。

## 失敗處理

- 不支援格式：標示 `略過` 與格式限制。
- 檔案被鎖定：標示 `失敗`，不重試寫入，讓使用者稍後重新排入待處理。
- 本機模型不可用或逾時：標示 `失敗`，保留待重試資訊。
- metadata 寫入或驗證失敗：保留備份與原檔，標示 `失敗`。
- 清冊或索引更新失敗：不得標記為完成，並列出可重試步驟。

## 延後項目（不屬於第一版）

- 常駐監看資料夾。
- 新檔案自動分析、metadata 寫入與清冊更新。
- 完整逐字稿、章節、逐鏡頭時間碼與複雜分類。
- 雲端 AI 分析或任何外部 API。
- 多使用者同步衝突處理與網頁搜尋介面。

## 驗收標準

1. 可遞迴掃描指定資料夾並以完整路徑／指紋避免重複項目。
2. 掃描階段不改動任何媒體檔。
3. 使用者可從待處理清單選取素材，並以本機 Qwen3-VL 完成描述、重點與關鍵字分析。
4. 每個成功項目都有驗證過的原檔 metadata、同名 Markdown、Excel 紀錄、本機索引與可還原備份。
5. 離線可用模糊搜尋與語意搜尋找出相近素材。
6. 在模型、格式或檔案錯誤時保留原檔，並在清冊顯示具體原因。
7. 執行期間不呼叫外部 API。
