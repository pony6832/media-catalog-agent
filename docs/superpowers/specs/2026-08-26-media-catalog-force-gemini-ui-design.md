# Media Catalog A+ 強制 Gemini UI 設計

**日期：** 2026-08-26  
**狀態：** 已批准設計，待書面規格審閱  
**適用版本：** Media Catalog A+ Stable  

## 1. 目標

在現有 Media Catalog A+ 狀態監控 UI 新增「強制 Gemini 強化」啟動鍵。使用者選定一個本機媒體根目錄後，可以選擇普通分析，或明確要求未審核的影片與照片使用 Gemini 3.7 Flash 加強辨識。

強制模式必須保留本地優先的安全基礎：先建立縮小預覽與本地分析，再把有限的影像證據送給 Gemini。系統不得上傳完整影片、原始大圖、本機完整路徑或 API Key。

## 2. 範圍與版本隔離

本功能只修改 Media Catalog A+ Stable 的 UI、CLI、supervisor、批次分析、片段分析、SQLite 狀態與 Excel 輸出。

本功能不得修改或覆蓋以下 Hybrid Lite 識別與產物：

- CLI：`media-catalog-hybrid-lite`
- 輸出資料夾：`媒體整理成果-HybridLite`
- SQLite：`catalog-hybrid-lite.sqlite`
- Excel：`媒體清冊-HybridLite.xlsx`
- Git 分支：`codex/hybrid-lite-v1`

本功能不提供單檔勾選、排程執行、API 費用換算、無上限 Gemini 呼叫或完整影音上傳。

## 3. UI 操作流程

### 3.1 資料夾選擇與清冊

1. 使用者按「選擇資料夾」。
2. 系統只建立或更新媒體清冊，不立即開始辨識。
3. 清冊完成後，UI 顯示影片數、照片數、總容量與可分析狀態。
4. UI 同時啟用兩個互斥的啟動鍵：
   - `開始／繼續`：普通模式，本地優先並只在資訊不足時自動呼叫 Gemini。
   - `強制 Gemini 強化`：橘色醒目按鈕，啟動本規格的強制模式。

### 3.2 強制模式啟動前檢查

按下「強制 Gemini 強化」後，系統依序檢查：

1. 目前沒有清冊或分析工作正在執行。
2. `GEMINI_API_KEY` 已設定且非空白。
3. 有效模型名稱為 `gemini-3.7-flash`。若使用者環境設定了 `GEMINI_MODEL`，其值必須完全等於 `gemini-3.7-flash`。
4. SQLite 與 Excel 清冊可讀取。

檢查失敗時不得啟動 worker，UI 顯示可操作的錯誤說明，但不得顯示 API Key 內容。

### 3.3 確認視窗

檢查通過後顯示確認視窗，內容包括：

- 未審核影片數。
- 未審核照片數。
- 因 Excel 狀態為「已審核」而跳過的數量。
- 正常強化請求上限：`未審核照片數 + 未審核影片數 × 12`。
- 若每個失敗請求都使用一次重試，最壞情況的 HTTP 嘗試上限為正常強化請求上限的兩倍。此數字是安全上限，不代表實際一定使用。
- 隱私提示：只上傳縮小照片預覽及影片代表影格，不上傳完整影音、原始大圖或本機完整路徑。

使用者取消時不得更改任何分析狀態、SQLite、Excel 或媒體來源。使用者確認後才建立強制任務。

### 3.4 執行中控制

強制任務執行期間：

- 狀態文字顯示 `Gemini 強制強化中`。
- 綠燈、目前媒體、影片／照片數、完成／總數、未完成數與 Gemini 使用量持續更新。
- 「選擇資料夾」、「開始／繼續」與「強制 Gemini 強化」停用。
- 只保留「安全停止」及不會改變分析狀態的輸出開啟功能。

## 4. 任務模式與持久化

### 4.1 明確模式

CLI 與 supervisor 必須使用明確的分析模式值：

- `auto`：現有普通分析。
- `force-gemini`：本規格的強制分析。

模式必須透過參數傳遞，不得依賴會殘留到其他程序的暫時環境變數。分析 run 在 SQLite 中保存模式與強制任務識別，使安全停止、worker 異常重啟或應用程式重開後仍能以原模式續跑。

### 4.2 任務準備

建立新的強制任務時：

1. 在重建 Excel 前先讀取並正規化「已審核」完整路徑集合。
2. 已審核項目不排入任務，既有描述、重點、關鍵字及審核狀態不得改變。
3. 未審核項目排入本次強制任務，但舊辨識內容在新結果成功保存前不得清空。
4. 同一強制任務已成功完成的照片或影片片段，續跑時不得重複呼叫 Gemini。
5. 新建另一個強制任務時，可以重新強化仍未審核的項目，但必須使用新的任務識別與用量紀錄。

## 5. 照片強制辨識

每張未審核照片執行以下流程：

1. 驗證來源仍存在且分析前後內容未改變。
2. 建立最長邊不超過現有安全尺寸的 JPEG 預覽。
3. 使用本地模型產生 `description`、`highlights` 與 `keywords`。
4. 以一張預覽、本地摘要及必要 OCR 文字建立 `GeminiSegmentRequest`。
5. 不論本地品質評分是否良好，強制呼叫 Gemini 一次。
6. Gemini 成功時以 Gemini 結果作為新分析；失敗時保存本地結果。

每張照片在同一強制任務中最多建立一個 Gemini 強化作業；該作業最多包含首次請求與一次失敗重試。

## 6. 影片強制辨識

### 6.1 本地片段分析

影片先依現有場景規則切段，單一長場景仍受既有最長片段時間限制。每個片段擷取候選影格，並選出 1～3 張代表影格完成本地分析。

### 6.2 Gemini 片段選擇

- 影片片段數不超過 12：全部片段排入 Gemini 強化。
- 影片片段數超過 12：最多選出 12 個片段。
- 選擇排序先考慮本地品質問題，再以時間均勻覆蓋補足名額，避免只處理影片開頭。
- 每個選中片段只上傳 1～3 張已縮放代表影格、本地分析與必要 OCR 文字。

### 6.3 結果彙整

Gemini 成功的片段使用雲端分析；未選中或 Gemini 失敗的片段使用本地分析。全部片段取得最佳可用結果後，再由現有本地摘要流程彙整整支影片。

每支影片在同一強制任務中最多強化 12 個片段；不得因重啟或恢復而突破此上限。

## 7. 失敗、重試與安全停止

### 7.1 Gemini 失敗

每次 Gemini 操作最多執行兩次嘗試，亦即首次失敗後自動重試一次。重試後仍失敗時：

- 不讓整批任務停止。
- 保存本地分析結果。
- 媒體資料庫狀態維持可供人工確認的已分析狀態。
- Excel「錯誤原因」欄顯示 `Gemini 強化失敗`，可附不含憑證與本機路徑的錯誤類型。
- UI 的失敗統計增加，接著處理下一個媒體。

### 7.2 本地階段失敗

若縮圖、片段擷取或本地分析失敗，以既有失敗與恢復機制處理。沒有安全預覽或本地分析時不得直接把原始檔送給 Gemini。

### 7.3 安全停止與恢復

安全停止必須完成目前可安全保存的階段、寫入 checkpoint，再退出 worker。恢復時延續原本的 `force-gemini` 模式，跳過同一任務中已成功完成的媒體與 Gemini 片段。

## 8. Excel 與資料保護

- Excel「狀態」下拉選單維持 `待確認,已審核`，不新增其他人工審核狀態。
- `已審核` 必須在所有 Excel 重建與強制任務中保留。
- Gemini 失敗提示寫在既有「錯誤原因」欄，不改變人工審核狀態設計。
- 完整路徑只保留在本機 SQLite／Excel 及檔案超連結，不進入 Gemini request。
- API Key 不得寫入命令列參數、SQLite、Excel、日誌、捷徑或錯誤文字。
- 原始照片與影片只讀；不得移動、改名、覆寫或產生來源旁的 sidecar。

## 9. Windows 程序行為

強制模式新增的 worker、FFmpeg、FFprobe、Ollama、watch、mcp-video-analyzer 與其他主控台子程序，必須沿用共用的 Windows 隱藏建立旗標。執行中不得反覆顯示 PowerShell 或黑色終端視窗。

## 10. 測試要求

### 10.1 UI 與模式

- 清冊完成前兩個分析啟動鍵停用。
- 清冊完成後普通與強制按鈕啟用且互斥。
- 強制確認視窗的影片、照片、已審核數、正常強化請求上限與含重試的最壞 HTTP 嘗試上限正確。
- 取消確認不產生狀態變更。
- 缺少 API Key、模型不符或 worker 忙碌時不得啟動。
- supervisor 與 CLI 正確傳遞及保存 `force-gemini`。

### 10.2 分析與保護

- 強制模式對品質良好的本地結果仍呼叫 Gemini。
- 普通模式維持原有條件式 Gemini 行為。
- 每張未審核照片每個任務最多建立一個強化作業，且最多重試一次。
- 每支影片每個任務最多 12 個片段，每片段 1～3 張縮圖。
- 超過 12 段時，選擇結果同時包含品質問題優先與時間覆蓋。
- 已審核項目不呼叫分析器且欄位不變。
- 原始媒體分析前後雜湊相同。
- repository、SQLite、Excel、日誌與啟動參數不含 API Key。

### 10.3 失敗與恢復

- Gemini 首次失敗後只重試一次。
- 第二次失敗保存本地結果、寫入安全錯誤提示並繼續下一項。
- 安全停止與 worker 重啟後不重複已完成的 Gemini 呼叫。
- 所有新增 subprocess 保持無主控台視窗。

## 11. 驗收

完成實作後必須：

1. 執行完整 pytest 測試並確認零失敗。
2. 執行安全與來源完整性測試。
3. 重新安裝 Media Catalog A+ Stable Skill 與桌面捷徑。
4. 實際啟動 UI，確認新按鈕、確認視窗、執行中狀態與按鈕停用規則。
5. 使用受控的小型測試媒體驗證一次強制流程，不使用大型真實資料夾消耗額度。
6. 驗證普通模式、Excel 已審核保護與隱藏子程序沒有回歸。
